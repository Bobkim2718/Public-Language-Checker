# 공공언어 검사기 v2.7 (Public Language Checker)

공공기관 내부 문서를 Windows PC에서 **로컬 분석**하여 공공언어 적합도와 개선 후보를 제시하는 데스크톱 앱입니다.

버전 2의 핵심 변화는 사용자가 이전 작업에서 `plainkorean.kr` 공개 API를 통해 확보해 둔 **쉬운 우리말 사전 스냅샷 3,581건**을 실제 문서 검사 엔진에 연결한 것입니다.

## 평가 구조

‘쉬운 우리말을 쓰자’의 **쉬운 공문서 쓰기 작성 원칙**을 참고해 다음 4개 영역을 100점으로 구성합니다.

| 영역 | 배점 |
|---|---:|
| 알기 쉬운 용어 | 35 |
| 알기 쉬운 문장 | 35 |
| 어문규범 | 20 |
| 한글 사용 | 10 |

> 표시되는 점수는 정부기관의 공식 평가 점수가 아니라 작성 원칙을 바탕으로 한 자체 분석 점수입니다.

## v2 핵심 기능

- Windows 데스크톱 UI(PySide6)
- HWPX / DOCX / PDF / TXT 로컬 텍스트 추출
- 문서 드래그앤드롭 및 직접 붙여넣기
- 공공언어 적합도 100점
- **쉬운 우리말 공식 사전 스냅샷 3,581건 자동 검사**
- 공식 사전의 `keyword → alt`를 실제 개선안에 사용
- 공식 사전 등재 표현의 **종류 수 / 사용 횟수** 표시
- OFFICIAL / CUSTOM / USER / MANAGED 출처 구분
- 긴 표현 우선 검사로 중복 검출 억제
- AI 같은 영문 약어의 단어 경계 검사
- 공식 사전에서 잡힌 영문 표현은 ‘한글 사용’ 영역에서 이중 감점하지 않음
- 검사 결과 항목 클릭 시 원문의 해당 위치로 이동
- 선택한 공식 용어의 **공개 API 상세 예문 조회**
- 사용자 사전
- 오프라인 JSON 업데이트
- HTTPS 관리형 사전·규칙 업데이트
- GitHub Actions Windows 테스트 및 단일 EXE 빌드

## 공식 사전 스냅샷

앱에 포함되는 빠른 로컬 검사 데이터는 다음 위치에 있습니다.

```text
data/official_terms/
  metadata.json
  official_terms_01.json
  ...
  official_terms_08.json
```

총 **3,581개 표제어**이며 앱에는 빠른 자동 검사를 위해 `keyword`와 `alt`를 포함합니다.

원본 수집 데이터에는 `example`도 포함되어 있으나, v2에서는 앱 용량과 검사 속도를 고려해 예문 전체를 내장하지 않습니다. 상세 예문이 필요한 경우 앱의 **공식 API 상세 조회** 기능으로 현재 API 응답을 확인합니다.

### 출처 구분

- **OFFICIAL**: 쉬운 우리말 사전 스냅샷 또는 공식 사전 업데이트
- **CUSTOM**: 앱 자체 공공문서 검사어
- **USER**: 사용자/기관이 직접 등록한 용어
- **MANAGED**: 관리형 업데이트 번들에서 추가한 일반 검사어
- **RULE**: 문장 길이, 표기, 한글 사용 등 규칙 기반 검사

현재 CUSTOM 기본 사전에는 공식 스냅샷과 겹치지 않는 표현만 둡니다.






## v2.7 표·구조 가독성 진단

공공언어 적합도 100점과 별개로 **표의 구조적 가독성**을 진단합니다. 이 진단은 정부기관의 공식 점수가 아니라 앱 자체의 보조 진단입니다.

### 지원 범위

- **HWPX**: 행·열, `cellAddr`, `colSpan`, `rowSpan`, 셀 문단 수, 중첩 표를 구조적으로 추출
- **DOCX**: 행·열, 가로/세로 병합, 셀 문단 수, 중첩 표를 구조적으로 추출
- **HWP 5.x**: 표 안의 글자는 공공언어 검사에 포함하지만 표 구조 진단은 아직 지원하지 않음. HWPX로 저장하면 구조 진단 가능
- **PDF / TXT**: 현재 텍스트만 검사

### 화면

별도의 **표·구조 가독성** 탭에서 다음을 확인할 수 있습니다.

- 감지된 표 수
- 표별 행 × 열
- 표 안 전체 문자 수
- 가장 긴 셀의 문자 수
- 빈 셀 수
- 병합 셀 수
- 중첩 표 수
- 표별 판정: 양호 / 검토 권장 / 개선 권장

파일 비교 화면에도 문서별 **표 가독성 상태와 표 수**가 표시됩니다.

### 현재 자동 진단 기준

- 7열 이상: 검토 권장
- 9열 이상: 개선 권장
- 한 셀 120자 이상: 검토 권장
- 한 셀 220자 이상: 개선 권장
- 한 셀에 5개 이상 문단
- 빈 셀 비율 35% 이상
- 병합 셀 비율 30% 이상
- 중첩 표 포함
- 25행 × 5열 이상의 큰 표

위 기준은 `data/rules.json > table_readability`에서 업데이트할 수 있습니다.

> v2.7은 **구조 가독성**을 평가합니다. 글꼴 크기, 색 대비, 실제 페이지에서의 셀 폭·줄바꿈, 인쇄 결과 같은 시각적 요소는 아직 평가하지 않습니다. 따라서 ‘표·구조 가독성’ 결과는 기존 공공언어 100점과 분리해서 봐야 합니다.

## v2.6 반복 지적 묶음 및 감점 보정

같은 표현이 문서에 여러 번 등장해도 같은 지적을 행마다 반복하지 않습니다.

예:

```text
피드백 | 6회 | 반응, 회신
모니터링 | 4회 | 점검, 관찰
```

검사 결과에는 **개선 항목 수**와 **전체 발생 횟수**를 분리해 표시합니다. 파일 비교 화면도 `12개 / 37회`처럼 보여 줍니다.

반복 감점은 선형 누적하지 않습니다.

- 최초 사용: 기본 감점
- 같은 표현의 반복: 소폭 추가 감점
- 반복 가산: 최대 5회까지만 반영
- 공식 사전 표현은 1회 사용 시 대체로 약 1점, 6회 이상 반복돼도 약 2점 수준이 되도록 설정
- 반복 계수는 `data/rules.json > repeat_scoring`에서 업데이트 가능

문장 길이처럼 **각 문장 자체를 따로 고쳐야 하는 지적은 문장별로 유지**합니다. 반대로 동일 용어, 동일 영문 표기, 연속 공백처럼 같은 성격의 반복 지적은 한 항목으로 묶습니다.

## v2.5 HWP 직접 분석

일반적인 **HWP 5.x 문서**는 더 이상 설치된 한/글 프로그램에 의존하지 않습니다.

- HWP의 OLE Compound File 구조를 로컬에서 직접 읽음
- FileHeader에서 압축·암호·배포용·DRM 속성 확인
- `BodyText/Section*` 스트림을 섹션 순서대로 읽음
- 압축 문서는 raw DEFLATE(zlib) 방식으로 해제
- `HWPTAG_PARA_TEXT` 레코드에서 문단 텍스트 직접 추출
- 표·그림 등 HWP 제어문자는 텍스트에서 제거하되, 표 셀 내부에 저장된 실제 문단 텍스트는 분석 대상으로 유지
- 문서 원문은 외부 서버로 전송하지 않음

직접 파싱이 불가능한 암호 문서, 일부 배포용/DRM 문서, HWP 5.x가 아닌 구형 문서는 설치된 한/글 Automation을 보조 경로로 시도합니다. 두 방식 모두 사용할 수 없으면 HWPX로 저장하도록 안내합니다.

## v2.4 HWP·표·드래그앤드롭 보완

- **레거시 HWP 지원**: Windows에 설치된 한/글 Automation을 이용해 HWP를 임시 HWPX로 로컬 변환한 뒤 분석합니다.
- **문서 외부 전송 없음**: HWP 변환도 사용자 PC의 한/글 프로그램에서 수행됩니다.
- **파일 경로 오분석 차단**: 파일 URL이 드롭되면 QTextEdit의 기본 경로/URL 삽입 동작을 실행하지 않습니다. 지원하지 않는 파일은 경고만 표시합니다.
- **HWPX 표 그리드 복원**: `cellAddr`, `colSpan`, `rowSpan`을 읽어 열 위치와 병합셀을 고려해 행 단위로 추출합니다.
- **중첩 표와 셀 내부 여러 문단**을 재귀적으로 읽고, 표가 문단 안에 들어 있는 일반 HWPX 구조에서 중복 추출하지 않습니다.
- HWPX 본문 XML이 비정상적이거나 비어 있으면 `Preview/PrvText.txt`를 보조 경로로 사용합니다.

> HWP 직접 분석은 **Windows + 한/글 설치 환경**이 필요합니다. 한/글 Automation 환경에서는 최초 파일 접근 시 한컴의 접근 승인 창이 나타날 수 있습니다.

최대 **20개 문서**를 한 번에 선택하거나 Windows 탐색기에서 함께 끌어놓아 분석할 수 있습니다.

파일 비교 탭에는 다음 항목이 문서별로 표시됩니다.

- 파일명 / 파일 크기 / 추출 본문 글자 수
- 총점
- 알기 쉬운 용어 /35
- 알기 쉬운 문장 /35
- 어문규범 /20

비교 표에서 문서를 더블클릭하거나 **선택 문서 상세 보기**를 누르면 해당 문서의 원문과 세부 개선 항목으로 이동합니다. 분석은 별도 작업 스레드에서 수행하므로 여러 파일을 처리하는 동안 화면이 멈추는 현상을 줄였습니다.

### 용량과 안전 한도

v2.3은 Windows GitHub Actions 러너에서 실제 3,581개 공식 사전으로 용량 벤치마크를 수행했습니다.

| 추출 텍스트 | 처리 시간 | Python 추적 메모리 피크 |
|---:|---:|---:|
| 0.1 MB | 0.06초 | 0.66 MB |
| 0.5 MB | 0.31초 | 3.31 MB |
| 1 MB | 0.65초 | 6.62 MB |
| 2 MB | 1.33초 | 13.24 MB |
| 5 MB | 3.71초 | 33.10 MB |
| 10 MB | 8.70초 | 66.19 MB |
| 20개 × 0.5 MB = 10 MB | 6.20초 | 12.41 MB |
| 20개 × 1 MB = 20 MB | 12.70초 | 24.68 MB |

이 수치는 **HWPX/DOCX/PDF 파일 자체의 압축·이미지 포함 용량이 아니라, 파일에서 추출된 텍스트의 UTF-8 기준 용량**입니다. PDF 이미지나 문서 삽입 그림이 크면 원본 파일 크기는 커도 실제 분석 텍스트는 작을 수 있습니다.

현재 앱의 보호 한도는 다음과 같습니다.

- 한 번에 최대 20개
- 원본 파일 1개 최대 100 MB
- 선택한 원본 파일 합계 최대 500 MB
- 문서 1개당 추출 본문 최대 5,000,000자
- 배치 전체 추출 본문 최대 10,000,000자

실사용 권장 범위는 **20개 이하, 추출 텍스트 총량 약 20 MB 이하**입니다. 이 범위는 실제 Windows 벤치마크에서 확인했습니다. 원본 파일 용량은 이미지·압축 방식에 따라 분석량과 직접 비례하지 않습니다.

## 개인정보 보호

기본 검사는 PC 내부에서 수행합니다.

- 문서 원문: 외부 서버 전송 없음
- 3,581개 공식 사전 대조: PC 내부 처리
- 문장 길이/표기 검사: PC 내부 처리
- 공식 API 상세 조회: 사용자가 선택하거나 직접 입력한 **낱말만** 전송

따라서 일반 문서 검사를 위해 문서 전체를 외부 API에 보내지 않습니다.

## 검사 방식 개선

v2에서는 표제어를 길이순으로 검사합니다.

예를 들어 사전에 `데이터`와 `데이터 바우처`가 모두 있을 때 문서에 `데이터 바우처`가 나오면 긴 표현을 먼저 잡아 `데이터`를 중복 검출하지 않습니다.

영문 약어는 문자 경계를 확인하므로 `AI`가 `MAIL`의 일부로 잘못 잡히는 식의 오검출도 방지합니다.

## 사전 및 규칙 업데이트

실행 파일과 검사 데이터를 분리했습니다.

### 사용자 사전

앱의 **사용자 용어 추가** 기능으로 등록한 데이터는 Windows 사용자 AppData에 저장됩니다.

### 오프라인 업데이트

기관망에서 인터넷이 제한되면 JSON 업데이트 파일을 배포할 수 있습니다.

```json
{
  "version": "2026.11.01",
  "official_terms": [
    {
      "keyword": "새 공식 표제어",
      "alt": "쉬운 표현"
    }
  ],
  "terms": [
    {
      "term": "기관 검사어",
      "alternatives": ["권장 표현"],
      "severity": "review",
      "source_type": "MANAGED"
    }
  ],
  "rules": {
    "sentence": {
      "recommended_max_chars": 100
    }
  }
}
```

`official_terms`는 공식 사전의 추가·수정용, `terms`는 기관/앱 관리 사전용입니다.

### 온라인 업데이트

`data/update_sources.json`의 HTTPS manifest를 통해 사전 델타와 문장 규칙을 배포할 수 있습니다. SHA-256 값이 제공되면 앱이 무결성도 검증합니다.

## 실행

Python 3.12 권장.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run.py
```

## Windows EXE

main 브랜치가 갱신되면 GitHub Actions의 `build-windows`가 단일 실행 파일을 생성합니다.

로컬 빌드:

```powershell
pyinstaller --noconfirm --clean --onefile --windowed --name PublicLanguageChecker --add-data "data;data" run.py
```
